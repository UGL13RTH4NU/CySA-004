SNORT Cheat Sheet / Reference

IDS vs IPS — know this cold
Mode / actionWhat happens
IDS + alertDetects a rule match and generates an alert. Traffic is not automatically blocked.
IPS + dropRuns inline and discards matching traffic. Use when the scenario requires automatic prevention/blocking.
Exam discriminator: “Detect / notify / monitor” → IDS / alert. “Automatically block / prevent / discard” → IPS / drop.
Canonical rule anatomy
[action] [protocol] [source IP] [source port] [direction] [destination IP] [destination port] ([options])
alert tcp any any -> 192.168.1.0/24 80 (msg:"Label"; content:"cmd.exe"; sid:1000001; rev:1;)
PieceMeaning
alert / dropAction.
tcpProtocol.
any anySource IP, then source port.
->Unidirectional source → destination.
<>Bidirectional: either endpoint can be source/destination.
192.168.1.0/24 80Destination IP/network, then destination port.
(...)Rule options.
Core option keywords
KeywordWhat to remember
msgHuman-readable alert message / label.
contentPayload string the rule is looking for.
sidSignature / rule identifier.
revRevision number for that rule.
Dion’s read-the-rule habit: first identify action, protocol, direction, and content match.
Alert-output anatomy

Dion calls out these fields in SNORT alert output:

  • Timestamp
  • [generator:sid:rev]
  • Message
  • Priority
  • Protocol
  • Source address/port
  • Destination address/port

Snort vs Suricata vs Zeek
ToolExam tell
SnortSignature/rule-based IDS/IPS; established Snort rule syntax.
SuricataMulti-threaded IDS/IPS/NSM, Snort-compatible syntax, EVE JSON; Dion contrasts it with single-threaded Snort 2.
ZeekNetwork security monitoring and rich behavioral/metadata logs rather than signature-rule alerting.
