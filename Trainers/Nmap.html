Nmap Cheat Sheet

Priority guide: CORE = directly emphasized in CertMaster/Sybex for CySA+; EXTENDED = valid Nmap knowledge retained from the prior trainer / reference sheet and useful for recognition.
Typed CLI practice — how answers are checked
  • Type the full command beginning with nmap; optional leading sudo is accepted.
  • Equivalent option order is accepted. For example, the target may appear before or after the options.
  • -p 22,443 and -p22,443 are treated the same; numeric comma-list order is ignored.
  • --script vuln and --script=vuln are treated the same.
  • Unrequested extra flags are marked as extra rather than silently accepted; the exercise trains the smallest command that meets the stated conditions.
Scope: the core typed bank follows Dion's CySA+ high-yield Nmap flags. A few additional command forms come from options already taught elsewhere in this trainer.
CySA+ high-yield Nmap core
OptionWhat to remember
-sSTCP SYN / half-open scan; CertMaster calls it a stealth scan.
-sUUDP port scan.
-pSpecify ports or ranges.
-snHost discovery only; do not perform a port scan.
-PRARP discovery on a local Ethernet network.
-sVService and version detection.
-OOS fingerprinting/detection.
-T4Aggressive timing template; faster scan assumptions.
-p-Ports 1 through 65,535 instead of the default common-port set.
CertMaster command anatomy: nmap -sS -T4 -O -sV -p- 192.168.50.9 combines SYN scanning, faster timing, OS detection, service/version detection, and the full port range against one target.
Do not confuse: -A is an aggressive feature bundle (OS detection + version detection + default scripts + traceroute). -T4 is an aggressive timing template.
Port states — read the scan
StateMeaning
openAn application is accepting connections/packets.
closedHost is reachable and replies (often RST), but nothing is listening on the port.
filteredNmap cannot determine the port state because filtering blocks useful probes/responses.
unfilteredReachable, but Nmap cannot tell open vs. closed; characteristic ACK-scan result.
open|filteredScan cannot distinguish open from filtered; common with UDP and some no-response scan types.
closed|filteredIdle scan cannot distinguish closed from filtered.
Exam cue: port state is evidence, not a vulnerability rating. A service on an open port may still be secure or vulnerable depending on configuration/version.
Scan techniques
OptionTechnique / distinction
-sSSYN / half-open; does not complete the normal TCP handshake.
-sTTCP connect; uses the OS connect call and completes a connection to open ports.
-sUUDP scan.
-sAACK scan; maps firewall rules/filtering, not which service is accepting connections.
-sNNULL scan; no TCP flags.
-sFFIN scan.
-sXXmas scan; FIN + PSH + URG.
-sWWindow scan; ACK-like technique that examines TCP window behavior on some stacks.
-sMMaimon scan; FIN/ACK probe.
-sIIdle scan using a suitable “zombie” host.

NSE scope: NSE can help with discovery, versioning, misconfiguration and vulnerability checks. It can also contain intrusive/exploit/DoS scripts, so script category matters.

CySA+ tool-selection pattern
NeedBest fit
Detailed host/port scan + service/OS fingerprint + NSENmap
Same Nmap engine but graphical profiles/topologyZenmap
Huge range as fast as possible; depth laterMasscan
Simple fast GUI sweep / lightweight discoveryAngry IP Scanner
Full vulnerability-management scanner with CVE/plugin depthNessus / OpenVAS-class tool, not Nmap alone
Pattern-recognition hook: depth / fingerprint / NSE → Nmap. Internet-scale speed → Masscan. simple GUI sweep → Angry IP Scanner.
Metasploit & Nmap integration
  • db_nmap = execute Nmap from Metasploit and automatically record results in the database.
  • db_import = import an already-created scan result file, including supported Nmap XML.
Correction from the old trainer: “imports Nmap results” is too vague for db_nmap. If the scan already exists as a file, think db_import; if Metasploit should run Nmap and record it, think db_nmap.
Privilege behavior & practical cautions
  • Many raw-packet scan modes are more capable with root/administrator privileges.
  • Without raw-packet privileges, Nmap can use a TCP connect scan for TCP port scanning rather than SYN scanning.
  • Full-port + version + OS + script scans can be noisy, slow, and operationally invasive.
  • Nmap results are inferences from network responses; filtering, unusual stacks, and deceptive responses can reduce certainty.
  • Only scan systems and networks you are authorized to test.
