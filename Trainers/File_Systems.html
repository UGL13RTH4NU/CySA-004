Cheat Sheet

1A · Windows File System
TermWhat to remember
C:\UsersPer-user profile folders and personal files.
C:\Program FilesTypical application installation location (64-bit apps on 64-bit Windows).
C:\Windows\System32Critical executables, DLLs, drivers/configuration needed by Windows.
C:\Windows\System32\winevt\LogsWindows event log files, including security logs.
bootmgrWindows Boot Manager.
winload.exeWindows OS loader.
ntoskrnl.exeWindows kernel.
winlogon.exeManages interactive user logon/logoff.
explorer.exeWindows shell/GUI: desktop, taskbar, file browsing.
Exam connection: NTFS Alternate Data Streams (ADS) can hide additional data behind a normal-looking file. Treat unexpected ADS content as a potential persistence/evasion clue.
1B · Windows Registry Root Keys
KeyCore distinction
HKLMMachine-wide hardware/software configuration; common to users.
HKCUSettings for the currently logged-in user.
HKCRFile associations and class/COM registration behavior.
HKULoaded user profiles/subkeys.
HKCCCurrent hardware profile/configuration gathered at startup.
Fast contrast: HKCU = current user. HKU = all currently loaded user hives. HKLM = machine-wide.
1C · Registry Hive Files
Hive/fileWhat to remember
SAMLocal account information; backs HKLM\SAM.
SECURITYSecurity policy / LSA-related security data. CertMaster describes it as linked to the security database.
SOFTWAREWindows and installed software settings.
SYSTEMDrivers, services, boot/control-set and file-system related configuration.
DEFAULTDefault/system profile-related settings.
NTUSER.DATPer-user registry settings in the user profile.
USRCLASS.DATAdditional per-user class/shell registration data under AppData\Local\Microsoft\Windows.
CertMaster erratum: The Module 3 page labels the first hive-file bullet SYSTEM but immediately describes the Security Accounts Manager. The standard hive is SAM; this trainer grades SAM as the correct term.
Supporting files: No extension = hive data; .LOG = transaction log; .SAV = saved/backup copy; the SYSTEM hive also has an .ALT backup in the source material.
1D · Windows System Processes
ProcessRole
wininit.exeInitializes critical Windows subsystems during boot.
lsass.exeSecurity policy and authentication; highly sensitive credential/security process.
svchost.exeGeneric host for Windows services; many instances can be normal.
explorer.exeGraphical shell (desktop/taskbar).
csrss.exeClient/Server Runtime Subsystem; essential Windows runtime/system process.
Analyst habit: Do not judge a process by name alone. Validate expected path, parent/child relationships, signature, user context, and resource/network behavior.
2A · Linux Standard Subdirectories
PathPurpose
/binEssential command-line binaries.
/bootBoot files.
/devDevice files/nodes representing devices. (CertMaster loosely calls these device drivers.)
/etcSystem/service configuration.
/homeNormal users' home directories.
/libShared libraries needed by kernel/essential binaries.
/mediaMount points for removable media.
/mntTemporary/manual mount points.
/optOptional/add-on software packages (for example, Nessus).
/procVirtual filesystem exposing live process/kernel information.
/rootRoot user's home directory.
/sbinSystem/administrative binaries, especially boot/admin tasks.
/sysVirtual filesystem exposing device/kernel information.
/tmpTemporary files; contents may not survive reboot.
/usrUserland programs/shareable files; contains important subdirectories.
/usr/binExecutable programs broadly available to users.
/usr/localLocally/custom-built or administrator-installed software.

High-yield contrasts: /proc = process/kernel state; /sys = device/kernel object view. /media = removable media; /mnt = temporary/manual mounts. /bin = essential user commands; /sbin = system/admin commands.
2B · Four Key Linux Directories
  • /etc — configuration for the system and services; think firewall, SSH, package/software settings.
  • /home — normal users' personal files and per-user resources.
  • /root — root user's home. Not the same as filesystem root /.
  • /var/log — primary location to investigate system/service logs.
Home shortcuts: $HOME expands to the current user's home path; ~ is a common shell shorthand for that home directory.
2C · Linux System Processes
ProcessRole
init / systemdFirst userspace process; bootstraps services. Modern distros commonly use systemd.
sshdAccepts incoming SSH connections.
cronRuns scheduled tasks/jobs.
kthreaddManages/creates kernel threads.
udevd / systemd-udevdHandles device events and hardware detection.
Process review tools: CertMaster highlights ps, top, and systemctl. Use them to inspect running processes/services and resource use.
CySA+ exam-oriented traps
  • Location matters. A legitimate process name running from an unusual path can be suspicious.
  • Multiple svchost.exe instances are normal. Investigate what service each instance hosts rather than assuming duplication is malicious.
  • /root vs /: one is a user's home; the other is the filesystem root.
  • HKCU vs HKU: current user versus loaded user profiles.
  • NTUSER.DAT is per-user. Most machine hives are under C:\Windows\System32\Config.
  • Filesystems are forensic context. Know where logs, configuration, user data, startup components, and persistence artifacts are likely to live.
