Process Lineage Cheat Sheet

What the exam is testing
Do not trust the process name by itself. Check the process's path, parent, privilege/user context, and signature. Dion's memory aid is P-P-P-S.
  • A legitimate process name in an unusual user-writable path is a red flag.
  • An unexpected parent/child relationship can reveal masquerading or malicious execution.
  • A signed/native binary can still be abused as a LOLBin. Behavior matters.
  • Process creation telemetry such as Windows Event 4688 and Sysmon Event 1 helps reconstruct lineage.
Windows · high-yield lineage
System └─ smss.exe (+ lineage anchor) ├─ csrss.exe ├─ wininit.exe │ ├─ services.exe │ │ └─ svchost.exe ★ │ └─ lsass.exe ★ [normally no ordinary children] └─ winlogon.exe interactive user shell: explorer.exe ★ └─ user-launched applications
ProcessWhat to remember
svchost.exeHosts Windows services. Expected parent: services.exe. Expected location: C:\Windows\System32. Multiple instances can be normal.
lsass.exeAuthentication/security. System32, SYSTEM context. Dion stresses that it should not spawn ordinary child processes.
explorer.exeGraphical user shell. Common parent/ancestor for applications opened interactively by the user.
wininit.exeInitializes critical Windows subsystems during boot.
csrss.exeEssential Client/Server Runtime Subsystem.
★ = directly emphasized by the supplied CySA+ study material. + = stable lineage anchor added to make the process tree teachable.
Windows · recurring suspicious patterns
  • explorer.exe → svchost.exe — wrong parent for svchost.
  • WINWORD.EXE / OUTLOOK.EXE / browser → powershell.exe or cmd.exe — source explicitly treats this as malicious/suspicious lineage.
  • lsass.exe → child process — critical deviation.
  • svchost.exe, lsass.exe, or similar system name under AppData, Temp, or Downloads — masquerading clue.
  • PowerShell -EncodedCommand, execution-policy bypass, or a download cradle — suspicious behavior.
  • certutil with -urlcache/-decode and external resources; mshta/regsvr32 spawning script engines or making network connections.
Linux · process anchors
ProcessWhat to remember
init / systemdFirst userspace process; modern systems usually use systemd as PID 1 to launch/manage services.
sshdHandles incoming SSH connections. An authenticated session can lead to a user's shell.
cron / crondRuns scheduled tasks; a job commonly spawns a shell/command.
kthreaddKernel-thread manager (commonly PID 2); not an ordinary user-space systemd service.
systemd-udevdHandles device events/hardware detection and is managed as a system service.
Linux is less rigid for this trainer. Distribution/service-manager differences make many exact parent relationships less universal. Focus on systemd/PID 1, known service roles, execution path, scheduled execution, and obviously anomalous behavior.
Linux · recurring suspicious patterns
  • Executable staged or launched from /tmp — common malware staging clue.
  • Executable launched from /dev/shm — important memory-backed/fileless clue in Dion's notes.
  • Unexpected systemd unit in /etc/systemd/system/ that launches a hidden or user-writable payload.
  • Process masquerading: a familiar service name running from a user-writable directory.
  • Linux LOLBins such as curl, wget, and nc are not malicious by name; suspicious command behavior and context make the difference.
Process injection & hollowing
  • Process injection: malicious code is placed inside a trusted running process. Look for behavior the trusted process should not perform, such as Notepad making network connections.
  • Process hollowing: a legitimate process is created/suspended, its memory is replaced, then it resumes. The process name can look normal while its behavior is not.
Sources & scope

Primary project sources: CompTIA CertMaster Perform (Windows/Linux processes and suspicious/rogue process analysis), Sybex CompTIA CySA+ Study Guide CS0-004 (abnormal OS process behavior / LOLBins), Jason Dion CS0-004 course notes OBJ. 1.2, and the existing File Systems trainer.

Supplementation: Stable Windows process-tree relationships (for example, wininit.exe → services.exe → svchost.exe) are included to make the lineage drill coherent. They are marked as lineage anchors rather than presented as an official CompTIA memorization list.

The suspicious drills intentionally avoid invented malware names. They use legitimate process names in wrong paths, wrong lineage, or malicious command/behavior contexts.
