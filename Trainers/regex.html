Regex Cheat Sheet

Dot vs literal period
.
Wildcard
one character
\.
Literal period

High-value trap: in an IP or domain pattern, an unescaped . means “any one character,” not a literal dot.
Core metacharacters & anchors
TokenMeaning
.Any single character (commonly except newline).
\Escape / introduces shorthand sequences.
^Start anchor; inside [^...], negates the class.
$End anchor.
\bWord boundary in engines that support it.
Character classes & shorthands
TokenMeaning
[abc]one of a, b, c
[a-z]one lowercase ASCII letter
[0-9]one decimal digit
[^0-9]one character that is not a digit
\d / \Ddigit / non-digit in common engines
\s / \Swhitespace / non-whitespace
\w / \Wword character / non-word character
Context matters: shorthand and Unicode behavior can differ by regex engine. [0-9] is an explicit ASCII digit range; \d is an engine-defined shorthand.
Quantifiers
*zero or more
+one or more
?zero or one / optional
{n}exactly n
{n,}n or more
{n,m}between n and m
Groups, alternation, boundaries & lookaround
(...)group; commonly captures matched text
(?:...)noncapturing group in common PCRE/Python-style engines
|alternation: left OR right
\1backreference to capture group 1 where supported
\bword-boundary position
(?!...)negative lookahead: what follows must not match
Grouping changes scope. ^(ERROR|WARN) anchors both alternatives. Quantifiers also apply to a whole group: (ab)+ repeats ab.
Security pattern examples
GoalDetection-style pattern
IPv4-looking\b\d{1,3}(?:\.\d{1,3}){3}\b
URL-likehttps?://[^\s]+
Email-like[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}
ID shape[A-Z]{3}\d{4}
32 hex chars[A-Fa-f0-9]{32}
64 hex chars[A-Fa-f0-9]{64}
Script extensions\.(ps1|bat|cmd)$
Encoded PowerShell-like-e(nc(odedcommand)?)?\s+[A-Za-z0-9+/=]{20,}
Detection ≠ strict validation. Shape recognition can deliberately overmatch. 999.999.999.999 fits a simple dotted-quad detector; 32 hex characters look hash-like but the regex alone does not prove which hash algorithm produced them.
Regex in security tools / dialects
  • Python: re.search() first match, re.findall() all matches, re.compile() reusable pattern.
  • Splunk: rex for regex-based extraction/replacement in SPL.
  • grep: pattern-search utility for logs/text; -E selects ERE.
  • BRE vs ERE: some operators require escapes in BRE that are direct operators in ERE.
  • POSIX classes: examples include [[:digit:]], [[:space:]], and [[:alpha:]].
Core concept first: regex engines are similar, not identical. Separate regex syntax from tool options/API syntax.
Read left to right
[A-Z]{3}\d{4}
1. [A-Z] uppercase letter → 2. {3} exactly three → 3. \d digit → 4. {4} exactly four.
\.(exe|dll)$
1. literal dot → 2. exe OR dll → 3. must occur at the end.

Do not guess from the overall shape. Identify one token or group, then ask what the next quantifier/anchor changes.

Common traps
  • * permits zero occurrences; + does not.
  • ^ is an anchor outside a class but negates at the start of [^...].
  • ? can mean optional, but it also appears inside advanced constructs such as (?!...).
  • Escape a metacharacter when you need its literal character.
  • Read complex patterns left to right instead of guessing from the whole string.
